# 実装・検証記録

2026-10-31（日本時間）

## 要件との照合

- 個人用サイトとしてSitesの新規プライベートプロジェクトを使用。
- 128個のエンジニア向けテンプレート。6カテゴリ、検索、並び替え、お気に入り。
- 8つのCanvasスタイルで自作し、PNGに書き出し。
- 128 / 256 / 512 / 1024 / 2048pxを選択。透明背景を保持。
- データはブラウザのlocalStorageに保存。アカウント用バックエンドや外部生成APIは不要。

## 分担とレビュー

主担当がUIと操作、保存、書き出し経路を実装。サブエージェントが128個のデータとCanvas描画、同梱フォントを実装。

サブエージェントが主担当のHTML・JavaScript・CSSを読み取り専用で独立レビュー。自身の描画実装は独立レビュー対象に含めていません。編集時の書体変更、カテゴリ切替時のフォーカス消失、ダイアログの名前、色入力のフォーカス表示の4件を修正し、再確認済み。

主担当も元の要望と最終成果物を自己点検。編集時の未指定の傾き、モバイルでの見出しの重なり、フォントライセンスへのパスも修正。

## 実行結果

- JavaScriptの構文確認：成功。
- Playwrightによる10件の主要経路テスト：成功。
- 全128個のテンプレートを境界設定（傾き12度・倍率1.3）で描画：担当者の検証で外周3pxへの描画なし。
- 5つのPNGサイズ：Blobのデコード後に縦横寸法を確認。
- 8種のスタイル：長文と最大倍率でも外周のクリッピングなし。
- 代表8テンプレート：編集を開いた前後のCanvas画像が完全一致。
- 幅320 / 390 / 768 / 1024 / 1440px：横のはみ出しなし。
- デスクトップ・モバイルのスクリーンショットを主担当が目視確認。

最初の並列テストはPythonの簡易サーバーで一部のアセット読込に失敗。並列アクセスを扱うNodeのローカルサーバーに切り替え、同じ10件が全件成功しました。

## 確認の範囲

Chromiumの自動テストとSafariの初期表示確認を実施。実機でのタッチ操作、OS固有の保存先UI、Safariの全経路、Firefoxは未検証。Sitesの配置完了はネイティブのデプロイ結果で別途確認します。

## パック追加と描画の修正

同日の追加依頼で、6種類のパックを追加。スタンダード、コードレビュー、タスク進行、リリース・運用、チームの会話、ひとやすみの各16個を、選んだ解像度の透過PNGを含む1つのZIPとして保存できます。全内容のプレビュー、生成進捗、キャンセル、失敗後の再試行に対応します。

認定バッジは対称な円形の輪郭と独立したリボンへ変更。インパクトも規則的な輪郭へ変更し、両方とも文字の実際の描画範囲を測って収めます。主テキストとサブテキストには別々の領域を確保し、装飾が文字へ重ならないようにしています。他の6スタイルには描画処理の変更なし。

主担当がパックUIとZIP機能を実装し、別担当が読み取り専用で独立レビュー。画面下のパックから生成したときの進捗表示・キャンセル操作の位置と、キャンセル後のフォーカス復帰を修正。描画は担当者が実装し、主担当が画像とコードを自己点検したうえで、別担当へ独立レビューを依頼しました。

- 構文確認、差分の空白チェック：成功。
- 既存10件とパック6件のブラウザテスト：16件すべて成功。
- 描画の衝突・画像端の欠けを確認する回帰テスト1件：成功。
- 全6パックを128pxで実ダウンロードし、標準のZIPライブラリで展開・CRC・各16枚のPNG実寸・一覧を確認：成功。
- スタンダードパックを2048pxで実ダウンロードし、各16枚が2048×2048pxであることを確認：成功。
- キャンセル時のダウンロード抑止、失敗時の操作復帰、生成中にサイズを変えても開始時のサイズを維持すること：成功。
- 320〜1440px幅のパック画面とプレビューダイアログ：横のはみ出しなし。
- 描画担当者の追加検証：576条件（日本語・英語・長文・改行、倍率、回転、4書体）で衝突・外周の欠けなし。30条件でPNG寸法・背景も成功。
- 独立レビュー担当が、進捗・キャンセルの修正を390px幅で再確認。描画も別途80条件で予約領域への収まりを確認し、比較画像を目視確認。追加の指摘なし。

PNG・ZIPの生成はすべてブラウザ内で実行し、ZIP用の実行時依存パッケージや外部サービスは追加していません。

## Next.jsへの移行

Next.js 16.4.3 / React 19.3.1 / TypeScript 5.9のApp Routerへ移行。ページとレイアウトはNext.jsで生成し、操作・保存・描画はClient Componentsで実行します。旧`dist/index.html`とDOMを直接書き換える`app.js`は削除し、検索・パック・編集・Canvas・ダイアログをReactコンポーネントへ分割しました。

`output: 'export'`で`out/`へ静的出力し、同じSitesプロジェクトとURLで配信します。ホスティング設定は出力先だけを変更し、アクセス設定は維持します。Next.jsの依存関係は追加しましたが、画像や保存内容を外部へ送る処理は追加していません。

お気に入りとマイスタンプは既存のv1キーと形式を維持。読み込みはhydration後に行い、最初の空状態を既存データへ上書きしません。描画・テンプレート・パック・ZIP・フォントCSS・画面CSSは、移動前の版からバイト単位で維持しています。

- TypeScript・エンジンの構文確認：成功。
- Next.jsの本番ビルド：成功。App Routerの`/`と404ページを静的生成。
- 本番出力に対する既存17件の回帰テスト：すべて成功。
- 追加3件の移行テスト：初期HTMLのNext.js生成、旧v1データの読み込み・更新・再読み込み、編集途中の画面移動と最新プレビューのPNG保存が成功。
- Next.js開発サーバーでも、保存互換・編集中の移動・最新描画・キャンセル・実行時エラーの4件を再確認して成功。React Strict Mode有効。
- デスクトップ・モバイルの画像を目視確認し、既存の見た目を維持。
- 独立レビュー担当がSSRとClientの境界、Effect・解除処理、非同期処理を確認。390px幅で保存・再読み込み・ダイアログ・キャンセル・キーボードとフォーカス復帰を操作し、追加の指摘と実行時エラーなし。

主担当がNext.js構成・状態管理・ダイアログ・保存互換処理を実装。2名が編集・描画のライフサイクルと一覧・パック画面を分担し、実装に参加していない別担当が独立レビューを実施。主担当も元の依頼・差分・検証結果を自己点検しました。

本移行の実操作確認はChromiumが対象です。Safariの全操作、Firefox、実機のタッチ・保存先UIは未検証。
